# 브라우저에서 과제 확인하기

학습관리시스템, 강의 페이지, 웹 문서가 작업의 출발점일 때 읽는다. 사용하는 브라우저 도구의 실제 안내가 조작 방법의 기준이다.

## 대상 탭과 상태

- 사용자가 지정한 탭이나 창을 우선 사용한다. 페이지 제목과 본문으로 과목·과제를 확인하고, 다른 작업자가 쓰는 탭과 충돌하지 않게 한다.
- 다른 컴퓨터나 계정의 세션이 현재 제공된 탭이라고 추정하지 않는다. 실제로 제어 가능한 대상만 확인한다.
- 로그인이나 접근이 필요하면 환경의 정상 인증 절차를 사용한다. 인증 URL, 쿠키, 접근 토큰을 작업 메모나 결과물에 복사하지 않는다.

## 자료별 확인 범위

과제란에서 필수 문항과 제출 형식을 확인하고, 해당 작업에 연결된 교안·첨부파일을 읽는다. 별도 요약 자료나 수정 공지도 결과에 영향을 주면 함께 확인한다.

필요하면 다음 정도로 상태를 남긴다. 아래는 가상 예시다.

| 자료 | 상태 | 작업에 미치는 영향 |
| --- | --- | --- |
| 과제 안내 | 필수 문항과 형식 확인 | 요구사항 대조 가능 |
| 연결된 교안 | 해당 실습 구간 확인 | 지정 절차 재현 가능 |
| 별도 요약 | 본문 미확인 | 요약 반영 여부는 판단 보류 |
| 강의 영상 | 슬라이드만 확인 | 음성에서 추가한 지시 미확인 |

## PDF 뷰어가 비어 있을 때

1. 아직 로딩 중인지, 실제 접근 오류인지 현재 화면이나 오류로 확인한다.
2. 페이지 수·본문 표시·스크롤 상태 등 새 정보가 생겼다면 다시 읽는다. 연결된 원본을 여는 정상 기능이 있으면 활용한다.
3. 새 정보 없이 반복하지 않는다. 계속 읽을 수 없으면 “페이지는 열렸지만 본문 미확인”처럼 정확한 상태와 필요한 자료를 알린다.

목록에 PDF가 있다는 것, 뷰어가 열렸다는 것, 본문을 읽었다는 것은 각각 다르다. 본문이 없는 상태에서 기억이나 다른 주차 자료로 필수 지시를 채우지 않는다. 독립적인 부분을 먼저 작성했다면 임시 결과임을 표시한다.

## 목록 정리와 제출 상태

- 목록 요청에는 과제명·마감·표시된 제출 상태·필요한 다음 행동을 필요한 범위에서 정리한다. 페이지에 없는 상태를 추정하지 않는다.
- 마감은 화면의 날짜와 시간대 표시를 따른다. 시간대를 알 수 없으면 그 한계를 밝힌다.
- 제출 완료는 실제 완료 표시나 제출 이력으로 확인한다. 파일을 만들거나 업로드 대기 화면에 올린 것만으로 제출 완료라고 말하지 않는다.
- 제출·메시지 발송·외부 공유는 사용자가 요청한 범위에서만 한다. 원격 제어 허용 화면의 링크나 세션 정보는 결과물에 포함하지 않는다.
