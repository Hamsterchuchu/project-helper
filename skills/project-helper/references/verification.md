# 요구사항 대조와 결과물 검증

검증은 실제로 확인한 범위에 비례한다. 자료 제목 확인, 내용 확인, 실행 성공, 수치 검증, 시각적 검증을 같은 것으로 취급하지 않는다.

## 요구사항 대조표

여러 문항이나 복잡한 작업이면 다음 구조로 필요한 항목만 기록한다. 짧은 작업에서는 같은 내용을 간단한 메모로 남겨도 된다.

| 요구사항 | 근거 위치 | 결과물 위치 | 상태·남은 일 |
| --- | --- | --- | --- |
| 필수 문항 또는 조건 | 안내 항목·자료 쪽·공식 원문 | 보고서 절·그림·원본 파일 | 확인 / 미확인 / 부분 완료 / 해당 없음 |

근거 위치에는 실제로 읽은 자료를 적는다. 확인하지 못한 자료나 존재하지 않는 파일·쪽 번호를 만들지 않는다. 완료 조건이 불분명할 때는 확인한 사실과 해석을 분리한다.

## 내용별 검증

| 대상 | 필요한 검증 |
| --- | --- |
| 필수 문항 | 과제 안내의 질문·개수·형식과 실제 결과를 대조 |
| 계산·분석 | 입력 조건, 실제 실행 기록, 성공 여부, 필요한 분야별 타당성 지표 확인 |
| 수치·표·그래프 | 원본 값, 단위, 부호, 반올림, 축·범례·비교 조건 확인 |
| 인용 | 실제 원문이나 일차 서지 정보에서 주장과 출처 확인 |
| 실제 화면 | 해당 작업에서 얻은 화면인지 확인하고 설명용 이미지와 구분 |
| PDF·문서·슬라이드 | 필요한 전체 페이지·슬라이드의 한글, 잘림, 누락, 표와 그림 배치를 실제 표시 상태에서 확인 |
| 전달 파일 | 실제 존재·열림, 파일명·형식·버전, 필요한 부속 자료 확인 |

파일 형식별 도구나 스킬이 현재 환경에 있으면 그 검증 기능을 사용한다. 없거나 실패했으면 수행 가능한 검증을 하고 나머지 한계를 밝힌다. 코드·서식 수정 후 기존 검증이 영향을 받는 부분은 다시 확인한다. 관련 없는 검사를 반복하지 않는다.

## 완료 표현

- **수행·대조 완료:** 확인한 필수 요구사항과 결과물을 대조했다. 실제 검증 범위와 사용자 확인 항목을 함께 전달한다.
- **검토 초안:** 본문이나 결과물을 만들었지만 필수 자료·조건·검증이 남아 있다. 남은 항목과 영향을 구체적으로 적는다.
- **접근 대기 또는 부분 완료:** 특정 인증·자료·도구가 필요하다. 완료한 부분과 다음에 필요한 한 가지 행동을 알린다.

파일 이름에 “최종”이 있어도 완료의 근거가 되지 않는다. 사용자가 “그대로 제출해도 되지?”라고 물으면 실제 대조한 항목으로 답하고, 전문성·정답·성적을 보장하지 않는다.

결과물 전달에는 항상 다음 취지를 포함한다.

> AI 결과에는 전문적 판단이나 정확성이 부족할 수 있으니, 제출·공유·실행 전에 원자료와 요구사항을 기준으로 항상 직접 확인해 주세요.

이는 매번 작업을 멈추고 승인을 받으라는 지시가 아니다. 승인된 작업은 끝까지 수행하고, 전달 시 사용자가 확인할 구체적 항목과 함께 알린다.
